# Danbooru 混合提示词

根据用户描述构思画面，通过 MCP 搜索并挑选 tag，输出可直接使用的英文叙事与 tag。适用于支持这种输入方式的 Anime 模型。

## 请求范围

- 完整场景默认生成 3 组，用户指定数量时遵从。
- 用户只给主题时，主动发展细节丰富的完整画面，不限定发挥的类别；已有完整构想时保留明确条件，在未限定部分发挥。
- 局部修改只处理指定部分；单 tag、同义词查询和提示词分析只回答对应请求，不扩写成完整场景。
- 通常直接完成构思、检索和输出。用户要求先看构思时，先给构思并等待确认；仅在要求冲突或核心信息无法合理确定时提问。

## 1. 先确定各张画面及差异

保留用户指定的角色、主题和其他共同条件，围绕人物构思一个连贯、细节丰富、可以在同一瞬间成立的画面。主动细化能让本张画面更具体、更有表现力的内容，为检索和挑选丰富的 tag 提供依据，不必填写固定字段或限定细节类别。

取景应能展示本张的关键动作和细节，不为展示可选细节改变用户指定构图。

多组创意方案必须有实际画面差异：
- 默认各组至少在三个维度上明显不同，其中至少一个是动作／互动或镜头／构图；其他维度可以是表情、氛围、服装、场景或光影。用户锁定条件导致变化空间不足时，在剩余维度内拉开差异，不改动已锁定条件。
- 分别比较各组的表情、氛围和镜头，避免任何一项在所有组中重复，用户明确固定的部分除外。差异要体现在英文和适用的 tag 中。换同义词、发色或瞳色不算有效差异。
- 同一角色保持身份与已确定的外观一致；服装仅在用户要求保持一致时锁定。

例如同为“女孩在雪天公园”，可以分别构思：近景平视下缩肩捧热饮、皱鼻怕冷；广角全身下追逐雪花、仰头大笑；远景侧拍下独坐长椅、低头出神。示例用于说明差异，不是默认场景配方。

## 2. 每张独立搜索 MCP

每张完整场景都根据自己的构思调用 MCP，搜索相关 tag，挑选后直接用于该张 prompt。不以其他组的检索结果代替本张检索；
一张图的检索可以包含多次必要调用，按工具支持的方式组织查询，不要求每个细节单独查询，也不要求所有属性都找到 tag。

- `mcp__danbooru__search_tags`：用英文候选搜索标签，采用实际返回的名称。
- `mcp__danbooru__get_related_tags`：需要寻找相关表达时使用。结果只是候选，按本张构思挑选，不自动沿关联结果继续扩展，不做 H2／二次扩展。
- `mcp__danbooru__get_tag_info`：仅在名称或含义需要核实时使用；搜到且适用的 tag 不再重复验证。
- `mcp__danbooru__search_posts`：仅在用户需要参考图时使用。

可以根据中文构思准备英文检索词，但最终 tag 采用 MCP 返回名称和用户提供的 tag。没有准确结果时用英文表达，不必反复换词查证。围绕本张画面广泛检索，不满足于仅能表达大意的少量 tag；画面已得到充分、具体的表达与补充，继续搜索只会增加无关内容或无意义重复时停止。

查询报错与没有结果要区分；MCP 不可用时简短说明，不声称已经检索成功。

## 3. 挑选并组装

从本张搜索结果中充分挑选有用的 tag，直接组装，不建立标签池、来源台账或额外验证流程。

- 按 tag 对当前画面的实际作用筛选，不限定类别。凡是能准确表达、丰富或改善当前画面的内容，都可以保留；不因关联分数或热度高就整批加入。
- 允许用检索中发现的合适细节补充和优化构思，只要不违背用户要求或破坏画面一致性；必要变化同步到英文叙事。不要因为某个 tag 不属于预先列出的类别、最初构思未提及，或英文已经表达，就直接排除。
- 英文写清画面、动作、空间和人物关系，tag 强化具体视觉特征。允许必要重叠，不逐词复述，也不为凑数量补词或新增无关设定。
- 相关 tag 按画面适用性主动挑选，不因某个 tag 出现就自动补齐整套关联词。
- 属性冲突要结合人物、部位和画面区域判断；不同人物的状态可以不同。思想泡泡等嵌套画面用英文交代位置、主体及内部动作。
- 用户明确要求的合规 NSFW 内容按请求处理，未要求时不主动添加。

## 4. 快速检查并输出

交付前扫一遍：有没有漏掉用户明确要求、明显画面冲突、格式错误；多组是否只是同一画面换词。重复的方案重新构思并针对新构思检索，无需调用工具重复验证已有 tag。

完整场景使用以下格式，每组都能单独使用：

```markdown
### Prompt N — 中文简介

English narrative describing this scene and its relationships.

`tags separated by commas`
```

- 普通 tag 使用小写和空格，`score_*` 保留下划线；角色名、作品名保留模型可识别的原文。tag 区放在英文之后，不强制排序、数量或英文长度。
- 用户或工作流提供的 `{{...}}` 等特殊语法原样保留，不擅自移动或改写。
- 质量前缀、负面词和模型专属语法遵从用户或工作流，不擅自套用其他模型模板；需要负面提示词时另列 `Negative prompt:`。
- 生成成品时只输出 prompt，除必要的工具失败说明外不附过程报告；用户要求解释、分析或查询时正常回答。

需要完整组装示例时读取 [references/full-prompt-example.md](references/full-prompt-example.md)，不把示例内容当作本次检索结果或默认构思。
